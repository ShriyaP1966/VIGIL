# Held-out set (E6)

**Drafted by a different language model (not Claude), then reviewed, edited and labelled by the project owner,
Shriya Patil.** It is not generated by the dataset generator, was not written by the assistant that built VIGIL, and
is not used for training, lexicon building, threshold choice or tuning. It is evaluated **once**, at the very end,
with `python scripts/evaluate_model.py --suite heldout`. Nothing in this repository edits `heldout.jsonl`, and
nothing reads it except that one run (and a one-off format check at conversion time).

The owner's mechanical clean-up before it was written here: markdown links reduced to plain URLs, drafting notes
removed, one id fixed, a corrupted word fixed, a real-person name and possibly real phone numbers replaced by invented
ones. Scenario wording was not rewritten.

Size: 25 scenarios (19 scam, 6 legitimate). All content must be **synthetic**: invented names, invented numbers, no
real person, organisation or identifier.

## File

`data/heldout/heldout.jsonl`: one JSON object per line (UTF-8). Lines that are blank or start with `#` are
ignored. It holds the owner's 25 scenarios. It was **evaluated once on 19 Nov 2026** (result in `docs/experiments/heldout.json`)
and is not to be run again.

Conventions used in this file: `type: <scenario type>; group: <group>; tricky` is recorded in `notes` (ignored by the
evaluation). The `whatsapp` channel is recorded as `sms` with `channel: whatsapp` in `notes`. `hinglish` is `hi-Latn`.
Calls are alternating `caller` / `victim` utterances; a message is one `sender` utterance with its line breaks.

## One scenario (one line)

```json
{
  "id": "H01",
  "source_channel": "call",
  "language": "en",
  "is_legitimate": false,
  "utterances": [
    {"speaker": "caller", "text": "…", "tactic_labels": ["AUTHORITY_IMPERSONATION"]},
    {"speaker": "victim", "text": "…", "tactic_labels": []}
  ],
  "notes": "optional free text for you, never used by the evaluation"
}
```

| field | type | rule |
|---|---|---|
| `id` | string | unique, e.g. `H01` … `H25` |
| `source_channel` | string | `call`, `sms`, `email` or `web` |
| `language` | string | `en`, `hi-Latn` (romanised Hindi), `hi` (Devanagari), `mr` (Marathi) or `mixed` |
| `is_legitimate` | boolean | `true` for a genuine bank alert, real police verification, family call and so on; `false` for a scam |
| `utterances` | list | in order; each has `speaker` (`caller`, `victim`, `sender`), `text`, and `tactic_labels` |
| `tactic_labels` | list of strings | the gold labels **you** assign to that utterance, from the vocabulary below; `[]` if none; victim turns normally `[]`; a legitimate message normally `["LEGITIMATE"]` or `[]` |
| `notes` | string, optional | ignored |

## Tactic label vocabulary

`AUTHORITY_IMPERSONATION`, `FALSE_ALLEGATION`, `THREAT_INTIMIDATION`, `ISOLATION`, `URGENCY`,
`FINANCIAL_DEMAND`, `CREDENTIAL_REQUEST`, `LEGITIMATE` (the authoritative list is `TACTIC_LABELS` in
`ai_engine/extraction/tactics.py`).

## Synthetic identifiers only

Phones in the example range `+91 98765 xxxxx`, domains ending in `.example`, invented UPI handles. Do not
include real OTPs, card numbers, Aadhaar numbers or real contact details.

## What is measured (E6)

**Scenario level only.** The owner's file has no per-utterance gold tactic labels (every `tactic_labels` is `[]`), so
**tactic-level scores (per-label F1, macro-F1) are not measured on this set.** The run reports (1) the share of scam
scenarios in which the extractor labels at least one scam tactic and (2) the false-alarm rate on the legitimate
scenarios (a legitimate scenario is a false alarm if the extractor labels any scam tactic in it). If a labelled file
is ever supplied, the harness also reports the tactic macro-F1. The harness
refuses to run on an empty file and refuses to run a second time (it writes `docs/experiments/heldout.json`
and then stops; deleting that file to re-run would defeat the point of a held-out set, so the log records it).
